# data/

Organized by lifecycle stage, not by topic — a file's folder tells you
whether it's safe to edit by hand, safe to delete and regenerate, or a
finished result.

## `input/`

Hand-curated or externally sourced. **Code never writes here** — if a
script appears to write into `input/`, that's a bug.

- `compounds/` — one `.xlsx` per compound (density, viscosity, critical
  properties, group-contribution data), used by both active and legacy
  systems. Flat, not split by system: a compound is reusable, a system is
  just a name list (see `COMPOUNDS_LIST` in `main.m`).
- `reference/` — literature correlation tables (GCVOL, Sastri-Rao, expDensity/expViscosity, variablesMatrix).
- `unifac/` — UNIFAC group and interaction-parameter tables.
- `experimental/` — raw measured data (`final_experiments.xlsx`, and the legacy `pcb77/` perstraction spreadsheet).

## `intermediate/`

Generated by one step, consumed by a later one. Regenerable in principle,
but currently tracked in git for the legacy System B pipeline (see below)
since the scripts that produced it are not fully reproducible as-is.

- `experiments/` — `.mat` structs derived from raw experimental data (System B).
- `compound-structs/` — serialized compound/UNIFAC structs and fit results consumed by downstream fitting/plotting scripts (`compoundDataFVP.mat`, `eqData.mat`, `FVP_results.txt`, `waterPOMS_fit_c.txt`, ...). Includes `compoundData.legacy.mat`, a duplicate found during the 2026-08 reorg, kept for reference — `compoundData.mat` is the live one `main/FVP_fit.m` reads.
- `property-fits/` — per-compound density/viscosity fit logs, rewritten every time `CompoundsLibrary` loads. Gitignored.

## `output/`

Terminal artifacts. Nothing in the codebase reads these back in. Gitignored.

- `figures/` — fit and result plots (`.jpg`).
- `results/` — reserved for future terminal result files.

## Two physical systems

See `docs/migration-plan.md` §2 for background. System A (benzene + methyl
acetate + polystyrene) is the active OOP target; System B (PCB77 +
water/extractant + POMS) is legacy, driven by `obsolete/` and `scripts/`.
Both draw compound data from `input/compounds/`.

## Known oddities

- `input/compounds/benzene.json` has no reader anywhere in the codebase — left in place rather than deleted, since its purpose wasn't clear during reorganization.
